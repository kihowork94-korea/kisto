# 키스토 (KISTO)

KIST AIX 성과공유회 출품용, "파편화된 AI 챗 대신 한 명의 연구 동료"
컨셉의 연구 동료 에이전트. 바탕화면 캐릭터 위젯(`widget/`) 하나가 입력창이고,
그 뒤에서 라우터 + 멀티 프로바이더 어댑터 + 4개 전문 모듈 + 메모리 + 연구
로드맵이 돈다.

## 구조

- `backend/config.py` — provider 등록과 모듈별 모델 매핑. 키가 없는 provider는
  `_FALLBACK_CHAIN` 순서로 자동 대체된다
- `backend/adapters/` — provider별 ModelAdapter 구현 (`base.py`가 공통 인터페이스)
  - `claude_adapter.py` / `openai_adapter.py` / `gemini_adapter.py` — API 키 방식
  - `claude_harness_adapter.py` — **API 키 없이** 로그인된 Claude Code CLI를 그대로 사용
- `backend/instructions.py` + 루트 `KISTO.md` — 사용자가 편집하는 지침 파일
- `backend/orchestrator/router.py` — 의도 분류 + 세션 스레드 상태 관리
- `backend/orchestrator/persona.py` — 어떤 모듈/모델이 답했든 "키스토" 말투로 통일
- `backend/modules/`
  - `research_coach.py` — 문헌/가설 (모듈 A)
  - `analysis_partner.py` — 데이터/코드 분석, 샌드박스 실행 + 자동 재시도 (모듈 B)
  - `writing_coach.py` — 집필 지원. 대필하지 않고 먼저 사용자 해석을 물음 (모듈 C)
  - `verifier.py` — 결과를 만든 것과 다른 provider로 교차검증 (모듈 D)
- `backend/memory/store.py` — 세션별 연구 스레드 + **연구 로드맵 진행 상태** + 모듈에 넘기는
  연구 맥락 요약(`thread_brief`)
- `backend/sandbox/executor.py` — 생성된 분석 코드 격리 실행 (첨부 파일은 작업 폴더에 복사)
- `backend/literature.py` — 실제 논문 검색 (PubMed → OpenAlex). 참고문헌 목록은 모델이 아니라
  코드가 만든다
- `backend/tracing.py` — 요청마다 어떤 에이전트가 어느 회사 모델로 몇 초 걸렸는지 기록 (발표 모드)
- `backend/privacy.py` — 주민번호·전화번호·이메일을 외부 모델로 보내기 전에 가림
- `backend/research_note.py` — 연구 주제를 연구노트(Markdown) 초안으로 정리

API: `POST /chat`(답변 + `review` 검토 노트 + `trace` 에이전트 흐름), `POST /upload`(CSV 첨부),
`GET /threads/{session}`(로드맵), `GET /threads/{session}/{index}/note`(연구노트)
`GET /progress/{session}`(지금 일하는 연구원), `GET /lab/session/{session}[/dashboard]`(연구실·대시보드),
`GET/PUT /lab/roles`(역할 부여)

**접근 제한**: 분석 단계가 LLM이 만든 코드를 이 PC에서 실행하므로, 아무 웹사이트나 백엔드를
부르지 못하게 막아 두었다. 백엔드가 처음 뜰 때 `data/.kisto_token`을 만들고, 위젯·연구실은 이 토큰을
헤더로 보낸다. 브라우저 요청(Origin이 붙는 요청)은 토큰이 있거나 테스트 페이지(`localhost:8500`)일
때만 받고, Host가 `127.0.0.1:8420`/`localhost:8420`이 아니면 거부한다 (DNS 리바인딩 방지).
`scripts/*.py`나 curl처럼 브라우저가 아닌 로컬 도구는 그대로 쓸 수 있다.

## 두 가지 실행 방식

**A. API 키 없이 (Claude Code 하네스 사용)**
`claude` CLI가 PATH에 있고 로그인되어 있으면 아무 설정 없이 그냥 실행하면 된다.
별도 과금키 발급이 필요 없어 개인 개발/데모에 적합하다.

**B. API 키 사용 (멀티 프로바이더)**
`.env.example`을 `.env`로 복사하고 원하는 키를 채운다. 세 개를 다 넣으면
모듈 B는 OpenAI 코딩 모델이, 검증 모듈 D는 Gemini가 맡는 식으로 교차검증이
실제로 서로 다른 회사 모델 사이에서 일어난다.

```bash
pip install -r requirements.txt
cd backend
uvicorn main:app --reload --port 8420
```

프론트엔드는 `fetch`를 쓰므로 file://로 열면 안 되고 HTTP로 서빙해야 한다:

```bash
cd frontend
python -m http.server 8500
```

그 다음 `http://localhost:8500/index.html` 접속 (`?debug=1`을 붙이면 어느 모듈/provider가
답했는지 보인다 — 데모에서는 붙이지 않는다).
`GET /health`로 현재 어떤 provider가 잡혔는지 확인할 수 있다.

전체 흐름(주제 → 분석 → 집필)이 실제 LLM으로 돌아가는지는 백엔드를 띄운 뒤
`python scripts/e2e.py`로 한 번에 점검한다. 단계별 모듈, 로드맵 %, 이종 모델 교차검증
여부, 소요 시간이 `data/e2e_result.json`에 남는다.

교차검증 효과는 `python scripts/verifier_eval.py [--verifier gemini]`로 잰다. 오류를 일부러
심어 둔 분석 결과 10건 + 문제없는 결과 2건을 검증 에이전트에 넣고 탐지율을 기록한다
(`data/verifier_eval_<모델>.json`). 검증 모델만 바꿔 같은 사례로 비교할 수 있다.

## 바탕화면 캐릭터 위젯 (`widget/`)

**`run.cmd` 더블클릭** 한 번이면 백엔드(창 없이)와 위젯이 같이 뜬다 (`-Lab`: 연구실 창도 열기, `-Chat`: 대화창을
펼친 채 시작). 바탕화면의 **키스토** 바로가기는 `run.cmd -Chat -Lab`을 실행한다. `claude` CLI가
PATH에 없어도 Claude 데스크톱 앱에 번들된 것을 찾아 쓴다.

- 투명·항상 위 창에 캐릭터만 떠 있고, 캐릭터가 없는 투명한 곳은 클릭이 바탕화면으로 통과한다
- 캐릭터 위 버튼 막대: **💬 대화** · **🏠 연구실** · **➖ 숨기기**(트레이 아이콘·`Ctrl+Shift+K`로 다시 보기) · **✕ 종료**
- 캐릭터 클릭 → 대화창 (상단에 연구 로드맵, 우상단 ✕나 Esc로 닫기), 드래그 → 위치 이동
- 답을 기다리는 동안 머리 위 말풍선에 **지금 일하는 연구원**("📚 문헌 연구원이 논문 찾는 중")과 경과 시간 표시,
  대화창을 닫아도 답이 오면 알려준다
- 로드맵 단계를 클리어하면 축하 연출
- 답변 아래 **검토 노트**: 다른 모델이 다시 따져본 결과를 접어 둔 노트로 보여준다
- **📎 CSV 첨부** (버튼 또는 대화창에 끌어다 놓기) → 분석 코드가 파일을 직접 읽는다
- 로드맵의 **📓 연구노트로 내보내기** → `문서\키스토 연구노트\`에 저장
- **발표 모드** (트레이 메뉴): 답변마다 `라우터 → 문헌 검색 → 연구 코치 → 교차검증` 흐름과
  각 단계의 회사 모델·소요 시간을 보여준다. 평소에는 꺼 둔다 (사용자에게는 키스토 한 명)
- 트레이 아이콘 메뉴: 보이기/숨기기(`Ctrl+Shift+K`), 위치 초기화, 새 대화 세션, 종료
- 발표 모드가 꺼져 있으면 내부 모듈/모델 정보는 전혀 보이지 않는다

### 키스토 연구실 (`widget/lab.html`)

위젯의 **🏠 연구실** 버튼(또는 트레이 메뉴)을 누르면 연구실 창이 열린다. 사용자는 연구실의
책임연구원(PI), 키스토는 연구실 매니저, 뒤에서 일하는 에이전트는 각자 자리가 있는 연구원이다.

| 자리 | 연구원 | 누르면 |
|---|---|---|
| 📚 서재 | 문헌 연구원 | 실제 검색된 논문 (링크·초록), 최근 가설 정리 |
| 🧪 실험대 | 분석 연구원 | 첨부 데이터, 분석 코드·결과·해석 |
| 💻 노트북 | 집필 연구원 | 연구자 해석, 초안, 연구노트 내보내기 |
| 🔍 검토 보드 | 외부 검토위원 | 모든 검토 기록 (누가 만들고 어느 회사 모델이 검토했는지) |
| 📋 퀘스트 보드 | — | 프로젝트별 5단계 진행도, 프로젝트 선택, 연구실 레벨 |
| 🚪 연구원 명단 | — | **역할 부여**: 연구원마다 담당 모델과 지침 지정 (`data/lab_settings.json`) |

상단 **📊 대시보드** 탭은 모든 프로젝트를 합친 진행을 한 화면에 보여준다: 핵심 지표(프로젝트·클리어한 단계·
논문·분석·교차검증·다른 회사 검토 비율·초안·연구원 작업 시간), 단계별 퍼널, 회사별 모델 호출, 연구원별
업무량·작업 시간, 프로젝트 현황표, 최근 활동 타임라인.

게임 요소도 전부 저장된 실데이터로만 움직인다.
- 책장에는 찾은 논문 수만큼 책이 꽂히고, 시험관에는 분석 횟수만큼 용액이 찬다. 검토 보드에는 검토 기록마다 메모지가 붙는다.
- 다음 단계를 하는 자리 위에 ❗ 퀘스트 표시가 뜬다.
- 단계를 하나 클리어할 때마다 별 1개, 별 5개마다 연구실 레벨이 오른다.

검토위원은 사용자가 같은 회사 모델로 지정해도, 다른 회사 모델이 있으면 그쪽으로 배정한다 (교차검증 원칙).

연구실 그림은 지금 코드로 그린 벡터 그림이다. `widget/lab-assets/`에 이미지를 넣고
`lab.json`에 적으면 코드 수정 없이 배경·가구 그림이 바뀐다 (규격은 `lab-assets/README.md`).

캐릭터는 `widget/character/`에서 교체한다. **검은 배경 mp4**를 넣으면 WebGL이 실시간으로
배경을 투명 처리하므로 별도 변환이 필요 없다. `character.json`:

| 키 | 의미 |
|---|---|
| `videos.idle` | 기본 영상 (필수) |
| `videos.thinking` / `talking` / `happy` | 상태별 영상 (선택). 없으면 idle + 효과로 대신한다 |
| `key.low` / `key.high` | 이 밝기 이하는 투명, 이상은 불투명 (0~1) |
| `crop.top` / `crop.bottom` | 영상 위/아래를 비율로 잘라냄 |
| `displayWidth` | 화면에 보일 캐릭터 너비(px) |

## 키스토에게 지침 주기 — `KISTO.md`

루트의 `KISTO.md`가 CLAUDE.md와 같은 역할을 한다. 성격, 답변 규칙, 연구 분야를
적어두면 모듈 A/B(해석)/C와 페르소나 레이어의 프롬프트에 자동으로 주입된다.
**매 호출마다 새로 읽으므로 서버 재시작 없이 바로 반영된다.**

코드 생성 단계에는 일부러 주입하지 않는다 — "코드만 출력" 형식이 깨질 수 있어서,
사용자 지침은 해석 단계부터 반영된다.

## 연구 로드맵 (`GET /threads/{session_id}`)

"대화를 주제별 폴더로 묶는" 기능이 아니다. 그건 이미 다른 AI 챗에도 있다.
여기서 추적하는 건 **각 연구 주제가 연구 프로세스의 어느 단계까지 왔는가**이고,
게임 퀘스트처럼 시각화된다.

```
주제 잡기 → 가설 세우기 → 분석 돌리기 → 교차검증 → 초안 쓰기
```

각 단계는 장식이 아니라 실제 저장된 데이터로만 판정된다 (가설이 저장돼야
2단계 클리어, 분석 결과가 있어야 3단계, 교차검증 기록이 남아야 4단계).
교차검증은 분석 모듈이 돌았을 때만 달성으로 인정한다 — 잡담까지 "검증 완료"로
치면 로드맵이 의미를 잃기 때문.

## 지금 이 단계에서 확인할 것

- "이 분야 연구주제 뭐로 잡을까" → research_coach가 가설 후보 + 되묻는 질문을 내는지
- 코드가 필요한 분석 질문 → 코드 생성 → 실행 → (에러 시 재시도) → 가설과
  연결지은 해석까지 하는지
- "논문 서론에 녹여줘" → 바로 초안을 안 주고 먼저 사용자 해석을 묻는지
- 대화를 진행하면서 상단 로드맵의 단계가 하나씩 채워지는지
- 주제 탐색 답변 끝에 실제 검색된 참고 논문 목록이 붙는지, 초안이 그 번호로만 인용하는지
- 테스트 페이지의 `?debug=1`, 위젯의 발표 모드는 개발·발표용 — 평소 사용에서는 끈다
  (사용자는 내부 구조를 몰라야 "한 명의 동료"라는 컨셉이 산다)

## 알려진 한계 / 다음 단계

- 코드 샌드박스는 로컬 subprocess 격리 수준의 프로토타입이다. 생성 코드가 pip로 패키지를
  받지 못하게만 막아 두었을 뿐(`PIP_NO_INDEX`), 파일·네트워크 접근은 막지 않는다.
  실제 배포 전에는 컨테이너 등 더 강한 격리가 필요하다.
- 하네스 어댑터는 매 호출이 독립된 1턴이라 CLI 쪽 대화 맥락은 이어지지 않는다
  (맥락은 키스토의 메모리 레이어가 담당한다).
- 라우터가 매 메시지마다 분류용 LLM 호출을 1회 더 하므로 약간의 지연이 있다.
- 메모리는 JSON 파일 하나 — 동시 사용자가 늘면 DB로 바꿔야 한다.
- 캐릭터 영상은 지금 대기(idle) 하나뿐이라 생각 중/축하 상태는 효과로 표현한다.
  상태별 영상을 추가하면 `character.json`만 고치면 된다.
- KIST-PaperBanana 등 사내 시스템 연동은 로드맵으로 남긴다.

## 제출용 신청서 (hwpx)

`python scripts/build_application_hwpx.py --template <서식 hwpx>`로 `docs/KISTO_AIX_신청서.hwpx`를 만든다.
목차는 공모전 신청서 항목을 따르고, 글꼴·제목 상자·개조식·표 모양은 `--template`으로 준 한글 파일의
스타일을 빌려 쓴다 (템플릿의 본문·그림·메타데이터는 가져오지 않는다). 붉은 `[ ]`는 제출 전에 채울 칸이고,
내용은 스크립트 위쪽의 `GENERAL`/`SUMMARY`/`BODY`를 고친 뒤 다시 실행하면 된다. 그림은 `docs/images/`.
만든 파일이 한글에서 실제로 열리는지는 `scripts/check_hwpx.ps1 <파일>`로 확인한다 (한글 COM으로 열어 PDF 저장).

연구실·대시보드 화면은 `scripts/ui_snapshot.js <세션ID>`로 캡처한다 (`widget`에서 Electron으로 실행, `data/snapshots/`).
