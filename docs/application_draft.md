**과제명(안)**: 키스토(KISTO) — 바탕화면에 사는 AI 연구 동료, 멀티에이전트 연구 파이프라인과 이종 모델 교차검증

**한 줄 요약**: 신입 연구자가 캐릭터 하나와 대화하면, 그 뒤에서 문헌·가설 → 분석 → 교차검증 → 집필 에이전트가 협업하고, 연구 진행 상황은 게임식 로드맵으로 쌓이는 연구 동료 에이전트

## 1. 추진배경 및 목적

**배경 — 직접 겪은 문제에서 출발**
- 신입 연구원으로서 코딩 역량은 있으나 도메인 배경지식이 부족해, **연구 주제 설정과 논문 작성 단계에서 가장 오래 막혔음**
- 기존 AI 챗봇은 질문 단위로 파편화되어 있어, 주제 → 가설 → 분석 → 논문으로 이어지는 **연구 맥락을 기억하지 못하고**, 답이 맞는지 **스스로 검증하지도 않음**
- 필요했던 것은 "답을 주는 도구"가 아니라 **연구 과정을 같이 걸어가는 선배/동료**

**목적**
- 연구 초기 단계(주제 탐색·가설·분석·초안)의 **소요 시간 단축**
- AI 결과를 **다른 회사 모델이 교차검증**해 과잉해석·통계 오류를 사전에 걸러내는 **신뢰성 확보**
- 대필이 아닌 **연구자의 해석을 먼저 묻는 방식**으로 연구윤리 준수와 신입 연구자의 학습 효과를 동시에 달성

## 2. AI 활용 내용

**구조 — "나만의 연구실": 매니저 한 명과 대화하면, 연구원들이 뒤에서 일한다**
- 연구자는 연구실의 **책임연구원(PI)**, 키스토는 **연구실 매니저**. 사용자 접점은 바탕화면 캐릭터 위젯 하나이고, 페르소나 레이어가 모든 응답을 "키스토 한 명"의 말투로 통일
- 뒤에서 일하는 에이전트는 연구실에 자리가 있는 **연구원**(서재의 문헌 연구원, 실험대의 분석 연구원, 노트북의 집필 연구원, 검토 보드의 외부 검토위원). **연구실 화면**에서 자리를 누르면 각 연구원이 한 일을 게임처럼 확인할 수 있고, 연구원마다 **담당 모델과 지침을 직접 부여**할 수 있음
- 오케스트레이터(라우터)가 메시지 의도를 분류해 4개 전문 에이전트로 연결
  - **A. 연구 코치**: **PubMed·OpenAlex에서 실제 논문을 검색**해 초록에 근거한 선행 연구 요약([번호] 인용), 후보 가설 2~3개 비교(참신성·실현가능성), 연구 동기를 되묻는 질문
  - **B. 분석 파트너**: 분석 코드 생성 → 격리 환경에서 실행 → 오류 시 자동 수정·재실행 → 가설과 연결한 해석
  - **C. 집필 코치**: **바로 대필하지 않고 연구자의 해석을 먼저 물은 뒤**, 그 해석을 반영해 초안 작성
  - **D. 교차검증 에이전트**: 결과를 만든 모델과 **다른 회사의 모델**이 과잉해석·통계적 의심·재현성 문제를 지적
- Google AI Co-Scientist, FutureHouse Kosmos 등의 멀티에이전트 연구 **패턴을 참고해 자체 재구현** (해당 서비스들은 공개 API가 없어 연동이 아닌 구조 차용)

**차별점 1 — 이종 모델 교차검증**
- Google Co-Scientist도 같은 모델 계열(Gemini) 안에서 검증함. 키스토는 **분석=OpenAI, 검증=Gemini처럼 서로 다른 회사 모델**이 검증하도록 설계
- 같은 모델이 자기 결과를 검증하면 같은 편향을 공유한다는 한계를 구조적으로 회피
- 실증 결과: `[ API 키 연동 후 scripts/e2e.py 결과 — 생성 모델 / 검증 모델 / 지적 사항 예시 ]`

- 검증 결과는 답변에 섞지 않고 **검토 노트**로 분리해 보여주고, **발표 모드**에서는 답변마다 `라우터 → 문헌 검색 → 연구 코치 → 교차검증` 흐름과 각 단계의 회사 모델·소요 시간을 그대로 보여줌
- 검증 효과 정량 평가 (`scripts/verifier_eval.py`): 통계·해석 오류를 하나씩 심어 둔 분석 결과 10건 중 **10건 탐지**, 문제없는 결과 2건에는 **오탐 0건** (2026-09-18, Claude 단독 기준). 다른 회사 모델 검증 결과 `[ API 키 연동 후 ]`

**차별점 2 — 환각 없는 문헌 근거**
- 모델이 참고문헌을 쓰지 않는다. 실제 검색된 논문에 번호를 매겨 주고 번호로만 인용하게 한 뒤, 참고문헌 목록은 **코드가 검색 결과에서 그대로 생성** → 존재하지 않는 논문 인용이 구조적으로 불가능
- 초안도 같은 목록에서만 인용하고, 검증 에이전트가 인용 문장과 초록을 대조

**차별점 3 — 연구 로드맵 (대화 폴더가 아닌 연구 진행도)**
- 대화를 주제별 폴더로 묶는 기존 AI 챗(Projects 기능)과 달리, 각 연구 주제가 **주제 잡기 → 가설 → 분석 → 교차검증 → 초안** 5단계 중 어디까지 왔는지를 게임 퀘스트처럼 표시
- 단계 달성은 장식이 아니라 **실제 저장된 데이터로만 판정**(가설이 저장돼야 2단계, 분석 결과가 있어야 3단계, 교차검증 기록이 있어야 4단계)

**차별점 4 — 연구 업무에 바로 쓰는 결과물**
- **CSV 데이터 첨부** → 분석 코드가 파일을 직접 읽어 실행
- **연구노트 내보내기**: 가설 논의·분석 코드와 결과·교차검증 기록·연구자 해석·초안·참고문헌·서명란을 연구노트 초안으로 자동 정리 (국가 R&D 연구노트 작성 부담 경감)
- **개인정보 자동 가림**: 메시지와 첨부 파일의 주민번호·전화번호·이메일을 외부 모델로 보내기 전에 가림 (영유아 연구 데이터 보호)

**차별점 5 — 게임처럼 쌓이는 연구 (연구실 화면)**
- 찾은 논문 수만큼 책장이 채워지고, 분석 횟수만큼 시험관이 차고, 검토 기록마다 검토 보드에 메모가 붙음
- 다음에 할 단계의 자리에 ❗ 퀘스트 표시, 단계 클리어마다 별 → 연구실 레벨 상승
- 모든 연출은 **실제 저장된 연구 기록으로만** 계산 (장식 아님)
- **📊 대시보드**: 모든 프로젝트의 진행(단계 퍼널), 교차검증 건수와 다른 회사 모델 검토 비율, 회사별 모델 호출,
  연구원별 업무량·작업 시간, 최근 활동 타임라인을 한 화면에 — 연구 책임자가 연구실 전체를 관리하는 화면

**차별점 6 — 기존 AI 데스크톱 펫과의 차이**
- 기존 제품(PetGPT 등)은 "캐릭터 옷을 입은 단일 LLM 챗봇"
- 키스토는 "캐릭터 뒤에 연구 파이프라인과 교차검증이 숨어 있는 구조"

**기술 구성**
- 백엔드: Python FastAPI, 모델 어댑터 4종(Claude API / Claude Code / OpenAI / Gemini) + 키 없는 provider 자동 대체
- 사용자 지침 파일(`KISTO.md`): 코드 수정 없이 키스토의 성격·답변 규칙·연구 분야를 바꿀 수 있고, 재시작 없이 즉시 반영
- 위젯: Electron 투명 창 + 캐릭터 영상 실시간 배경 투명 처리(WebGL), 투명 영역 클릭 통과, 단계 클리어 연출

## 3. 주요 성과 및 개선 효과

**동작 검증 (엔드투엔드)**
- 신생아·영유아 비침습 연구 시나리오로 주제 탐색 → 데이터 분석 → 교차검증 → 논문 서론 초안까지 **실제 LLM 응답으로 전 과정 자동 점검 통과**, 로드맵 0 → 40 → 80 → 100% 달성
- 분석 단계에서 교차검증 에이전트가 **표본 크기 대비 과잉해석, 검정 방법 선택 근거 부족** 등을 실제로 지적
- 문헌 단계에서 실제 논문(예: Villarroel 외 2019, *npj Digital Medicine* — NICU 미숙아 비접촉 모니터링)을 근거로 인용하고, 검증 에이전트가 "미숙아 NICU 연구를 가정 환경으로 일반화했다"처럼 인용과 초록의 불일치를 잡아냄
  (※ 데모 분석 데이터는 시연용 가상 데이터)

## 4. 확산 가능성

- **분야 무관**: 연구 분야는 `KISTO.md` 한 파일로 지정 → 재료·바이오·의공학 등 KIST 전 분야에 코드 수정 없이 적용
- **모델 교체 가능**: 모듈별 모델을 설정으로 교체. 보안 요구가 높은 과제는 사내 LLM으로 대체하는 구조로 확장 가능
- **도입 비용 낮음**: 개인 PC에서 실행 파일 하나(`run.cmd`)로 동작. 별도 서버 불필요
- **신입 온보딩**: 연구실 선배가 매번 설명하던 연구 프로세스를 로드맵으로 구조화 → 신입 연구원 교육 도구로 활용
- **향후 계획**: KIST 사내 시스템(예: KIST-PaperBanana) 연동, 연구실 단위 공유 메모리, 컨테이너 기반 분석 샌드박스로 보안 강화
