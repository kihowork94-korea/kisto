# 심사위원 관점 점검 — 약점, 차별성, 예상 질문

> 2026-09-18 작성. 심사배점: 창의성 40 / 업무활용성 30 / 확산가능성 30.
> "이번에 고친 것"은 이 점검을 바탕으로 제품에 반영한 내용이다.

## 1. 가장 먼저 나올 질문: "ChatGPT(또는 Claude)로도 되는 거 아닌가요?"

범용 AI도 대화를 기억하고, 코드를 실행하고, 웹을 검색하고, 프로젝트 폴더도 있다.
그래서 **기능 목록으로 비교하면 진다.** 답은 기능이 아니라 **구조**로 해야 한다.

| 관점 | ChatGPT / Claude (범용 챗) | 키스토 |
|---|---|---|
| 누가 검증하나 | 답을 만든 모델이 스스로 (같은 편향 공유) | **다른 회사 모델**이 매 답변을 따로 검토하고, 그 결과를 "검토 노트"로 분리해 보여줌 |
| 문헌 근거 | 웹 검색 결과를 요약 (인용 형식·실재 여부는 모델 몫) | PubMed·OpenAlex 실제 논문의 초록만 근거로 쓰고, **참고문헌 목록은 모델이 아니라 코드가 붙임** → 없는 논문 인용이 구조적으로 불가능 |
| 연구 과정 | 대화가 쌓일 뿐, "지금 연구가 어디까지 왔는지"는 사용자가 기억 | 주제마다 5단계 로드맵, **저장된 실데이터로만** 단계 판정 |
| 초안 작성 | 요청하면 바로 대필 | **연구자의 해석을 먼저 묻고** 그걸 반영 (연구윤리 + 학습) |
| 결과물 | 대화 기록 | **연구노트 초안**(코드·결과·검증·해석·참고문헌·서명란)으로 내보내기 |
| 민감 데이터 | 붙여넣은 그대로 전송 | 주민번호·전화번호·이메일을 **보내기 전에 자동으로 가림** (첨부 파일 포함) |
| 사용 방식 | 브라우저 탭을 열고 매번 맥락 설명 | 바탕화면에 상주하는 캐릭터 하나. 맥락은 키스토가 들고 다님 |

**한 문장 답변**: "범용 AI는 똑똑한 개인 한 명이고, 키스토는 역할이 나뉜 연구팀입니다.
문헌 담당은 실제 논문만 근거로 쓰고, 분석 담당은 코드를 돌리고, **다른 회사 출신 검토자**가
그 결과를 반박하고, 집필 담당은 연구자의 해석을 먼저 듣습니다. 연구자는 그 팀과 따로 대화할
필요 없이 키스토 한 명과만 이야기합니다."

## 2. 심사 항목별 약점과 대응

### 창의성 (40)

| 약점 (점검 시점) | 왜 문제인가 | 대응 |
|---|---|---|
| 핵심 차별점(이종 모델 교차검증)이 화면에 안 보임 | "내부 구조를 숨긴다" 원칙 때문에 심사위원은 검증이 일어났는지조차 알 수 없음 | **검토 노트**(모든 사용자에게 보임, 모델 이름은 안 보임) + **발표 모드**(트레이 메뉴. 답변마다 `라우터 → 문헌 검색 · PubMed 6편 → 연구 코치 · Claude → 교차검증 · Gemini` 흐름과 소요 시간 표시) |
| "캐릭터 + 챗봇"으로 보일 위험 (기존 AI 데스크톱 펫) | 캐릭터가 겉포장처럼 보이면 창의성 점수 손해 | 발표 모드로 캐릭터 뒤의 파이프라인을 직접 보여줌. 로드맵 단계 클리어 연출은 실데이터 기반 |
| 멀티에이전트 자체는 새롭지 않음 (MetaGPT, CrewAI 등) | "에이전트 여러 개"만으로는 차별화 안 됨 | 차별점을 **연구 특화 역할 + 이종 검증 + 대필 금지 + 연구노트**로 좁혀서 말한다 |

### 업무활용성 (30)

| 약점 | 대응 |
|---|---|
| "문헌 조사"라면서 실제 논문을 인용 못 함 ("구체적 논문은 인용할 수 없다"고 스스로 말함) | **PubMed·OpenAlex 실제 검색** → 초록 근거로 요약, [번호] 인용, 참고문헌 목록 자동 첨부. 초안도 이 목록에서만 인용 |
| 데이터를 채팅에 숫자로 타이핑해야 함 | **CSV 첨부** (📎 버튼 또는 대화창에 끌어다 놓기) → 분석 코드가 파일을 직접 읽음 |
| 결과물을 밖으로 꺼낼 방법이 없음 | **연구노트 내보내기** — 국가 R&D 연구노트 작성 의무와 직결. 서명란 포함 |
| "맥락을 기억하는 동료"라는 주장과 달리, 각 모듈은 매번 현재 메시지만 받았음 | 스레드별 **연구 맥락 요약**(가설, 분석 결과, 연구자 해석, 첨부 파일, 최근 대화)을 모든 모듈에 주입 |
| 응답이 느림 (API 키 없는 구성에서 1~3분) | API 키 구성으로 시연. 생각 중 말풍선에 경과 시간 표시로 체감 대기 완화 |

### 확산가능성 (30)

| 약점 | 대응 |
|---|---|
| KIST 연구 데이터를 외부 AI로 보내는 보안 문제 | 개인정보 자동 가림 + 모델 교체 구조(사내·로컬 LLM으로 대체 가능)를 근거로 답변. **완전한 비식별화 도구는 아니라는 점은 솔직히 말한다** |
| 분석 코드 샌드박스가 약함 | 현재는 로컬 격리 + 패키지 설치 차단 수준. "배포 시 컨테이너 격리"를 로드맵으로 명시 |
| 신생아 데모 = 특정 분야 전용 아니냐 | 연구 분야는 `KISTO.md` 한 파일로 바뀜. 논문 검색도 PubMed(생의학) + OpenAlex(전 분야) |

## 3. 예상 질문과 답변

**Q. 교차검증을 하면 정확도가 실제로 올라가나요?**
A. 오류를 심어 둔 분석 결과 10건으로 쟀을 때 10건 모두 탐지, 정상 결과에 대한 오탐 0건이었다. 다만 사례가 쉬운 편이라 이종 모델 효과는 `[ 키 연동 후 비교 ]`. 실제 리허설 사례도 있다: 리허설에서 검증 에이전트가
"상관계수는 일치도가 아니다", "반복측정이면 p값이 부풀려진다", "오차가 전부 작은 정수라 합성
데이터 같다"를 잡아냈다. `[ API 키 연동 후 이종 모델 검증 사례 추가 ]`

**Q. 환각(없는 논문 인용)은 어떻게 막나요?**
A. 모델이 참고문헌을 쓰지 않는다. 검색된 실제 논문에 번호를 매겨 주고 번호로만 인용하게 한 뒤,
목록은 코드가 검색 결과에서 그대로 만든다. 검증 에이전트는 인용 문장이 초록과 맞는지도 확인한다.

**Q. 대필하지 않는다면서 초안은 쓰잖아요?**
A. 연구자의 해석을 먼저 받아야만 초안을 쓴다. 해석 없이 "써줘"라고 하면 질문으로 돌려준다.
연구노트에는 연구자 해석이 따로 기록된다.

**Q. 에이전트가 여러 개면 비용·시간이 몇 배 아닌가요?**
A. 요청당 모델 호출 3~5회. 해석 묻기처럼 검증할 게 없는 단계는 검증·페르소나를 건너뛴다.
발표 모드에서 단계별 소요 시간을 그대로 보여준다.

**Q. Co-Scientist 같은 걸 연동한 건가요?**
A. 아니다. 공개 API가 없다. 멀티에이전트 *패턴*을 참고해 직접 재구현했다.

**Q. 'AI 에이전트 회사' 컨셉은 MetaGPT·ChatDev에도 있지 않나요?**
A. 구조(역할 나눈 에이전트)는 같은 계열이다. 다른 점은 ① 연구 과정에 맞춘 역할(문헌·분석·검토·집필)과
대필 금지 원칙, ② 검토자를 **다른 회사 모델**로 강제하는 교차검증, ③ 연구 기록이 게임처럼 쌓이는
연구실 화면과 연구노트 산출물이다. 소프트웨어를 자동으로 만드는 게 목적이 아니라, 연구자가 과정을
주도하고 에이전트는 연구원으로 돕는 구조다.

**Q. 왜 굳이 캐릭터인가요?**
A. 연구 초년생에게 필요한 건 도구 여러 개가 아니라 "물어볼 수 있는 선배 한 명"이다.
입력창이 하나라서 사용자는 어떤 도구를 써야 할지 고민하지 않고, 역할 분담은 뒤에서 일어난다.

## 4. 이번에 고친 것 (제품 반영)

1. 모든 모듈에 스레드별 연구 맥락 주입 (가설·분석·해석·첨부파일·최근 대화)
2. 실제 논문 검색 (PubMed → OpenAlex), [번호] 인용, 코드가 만드는 참고문헌 목록, 초안 인용 연결, 검증 에이전트의 인용 대조
3. 검토 노트 (교차검증 결과를 답변과 분리해 접힌 노트로)
4. 발표 모드 (에이전트·회사 모델·소요 시간 흐름 표시)
5. CSV 첨부 → 분석 코드가 파일을 직접 읽음
6. 연구노트 내보내기 (문서\키스토 연구노트)
7. 개인정보 자동 가림 (메시지·첨부 파일)
8. 연구실 컨셉 + 게임식 연구실 화면 + 📊 대시보드 (전체 진행·회사별 모델 호출·연구원별 업무/시간·타임라인)
9. 로컬 백엔드 접근 제한 (토큰·Origin·Host 검사) — 아무 웹사이트나 연구 기록을 읽거나 분석 코드 실행을
   유도하지 못하게. 보안 질문이 나오면 개인정보 가림과 함께 근거로 든다
10. 교차검증·페르소나 병렬 실행으로 응답 시간 단축 (데모 시나리오 435초 → 297초)

## 5. 아직 남은 약점 (정직하게 인정할 것)

- 교차검증 정량 평가는 `scripts/verifier_eval.py`로 추가했다: 오류 10건 중 10건 탐지, 정상 2건 오탐 0건
  (Claude 단독, 채점도 Claude). **한계**: 사례가 교과서적이라 쉬워서 천장 효과가 있고, 채점 모델이
  같은 회사다. 이종 모델 효과를 보이려면 더 미묘한 오류 사례(예: 교란 변수가 숨은 설계, 단위 착오,
  잘못된 자유도)를 추가하고 채점은 사람이 하거나 제3의 모델로 해야 한다
- 실측 before/after 수치는 연구자 본인 측정 필요
- 샌드박스 격리 수준, 개인정보 가림의 한계 (패턴 기반)
